# DriveCompose：CVPR 论文定位、方法与实验方案

更新：2026-10-19。用户条件：目标 CVPR；Waymo 798 个训练场景、202 个验证场景；64 张 H20。本文是基于当前源码与近邻检索形成的研究方案，未填入未执行的实验结果。检索记录见 [paper-literature-audit.md](paper-literature-audit.md)。

## 1. 推荐的论文主线

**从不完整驾驶日志中，观测锚定地联合补全背景和规范资产，得到能够供多条状态轨迹复用的可组合三维高斯世界。**

建议标题：**DriveCompose: Observation-Anchored Joint Completion of Composable Gaussian Driving Worlds**。

中文工作标题：**DriveCompose：面向可组合驾驶世界的观测锚定联合高斯补全**。

最值得投入实验的是：背景与资产的联合条件能否改善未见区域的恢复，同时将已见区域的渲染退化控制在预先规定的范围内。固定世界和仿真闭环承载这个结果的用途；它们自身已有充分先例。

## 2. 研究问题

输入是一段有标定的多相机日志，仅覆盖场景与交通参与者的部分表面。输出包含背景、天空、规范车辆和可驱动人体的固定世界。研究目标包括：

1. **未见区域补全。** 当新相机位置、车辆转向或人体姿态暴露未观测表面时，提供完整且合理的几何与外观。
2. **观测保持。** 生成的内容应兼容原始观测，既保护已见表面的参数，也限制新增表面对原视角造成的错误遮挡。
3. **组合后的可用性。** 同一身份的规范资产可以在不同状态下复用，补全质量在新视角和预先规定的状态干预中仍成立。

可写为：

\[
\mathcal W \sim p_\theta(\mathcal W\mid\mathcal L),\qquad
o_k=\mathcal R(\operatorname{Compose}(\mathcal W,s_k),\mathcal C_k),\qquad
s_{k+1}=F_{\mathrm{dyn}}(s_k,\pi(o_k),\Delta t).
\]

这里的随机补全发生在构建 \(\mathcal W\) 时；同一世界的后续轨迹共享该补全结果。\(F_{\mathrm{dyn}}\) 是接入的动力学后端。当前项目学习的是世界内容恢复与补全，状态转移由该后端承担。

## 4. 创新候选与最近邻差异

### C001：异构规范表示中的场景—资产联合补全

背景、车辆、人体分别保留合适的坐标空间与解码约束，通过共同宽度潜码及全局记忆交换场景条件。规范坐标稳定资产身份，参考世界坐标提供与道路、其他资产的空间关系。预期贡献是联合条件带来的补全收益。

**需要的证据：** 在同一恢复前端、同一 codec、同一查询支撑与训练预算下，完整方法优于禁止跨组 token 交换的独立补全；收益出现在未见表面与场景一致性上。

当前联合机制由分组局部注意力和全局记忆读写构成，还没有显式的接触关系图或碰撞推理。若联合 / 独立实验没有稳定差距，应先修改机制或缩小主张；不能只把标准注意力命名为新模块。

### C002：将观测保持落实到潜码、空域与渲染三个层面

可靠观测潜码每步固定，自由空间在潜码积分和高斯不透明度两个位置受约束；固定逐查询 codec 保持可靠查询的原始解码输出。候选世界还需要在原视角下检查新增表面造成的退化。

**需要的证据：** 相对软观测拟合，在未见区域质量与已见区域退化之间取得更好的权衡；同时公开全部场景的构建通过率、拒绝率与有效域覆盖。检查使用的预测深度只构成观测一致性依据，独立几何评测应使用另行获取的真值。

硬条件采样和潜码补全已有先例，这里的创新候选是它们在异构三维可组合世界中的完整设计及实证效果。

### C003：补全后的世界可被不同状态轨迹复用

同一次构建产生固定背景与规范资产，车辆整体变换、人体按骨架变形。状态变化时直接装配和渲染已有三维内容。

**需要的证据：** 预先定义的新相机轨迹、车辆转向 / 位置以及人体姿态条件下，原始高斯渲染仍有合理质量与有效域；在线成本单独报告。数组不变、刚体距离不变和相同状态装配一致属于实现检查，不能单独证明这种应用能力，也不宜作为独立主要创新。

## 5. 方法章节建议

### 5.1 轨迹关联与异构规范支撑

共享编码器预测特征、深度、置信度、实例标签、相机与资产状态。背景以深度抬升的可靠锚点和有限网格支撑，车辆以轨迹规范化锚点和局部包围体网格支撑，人体使用身份模板规范表面，天空使用单位方向。

将同一查询在各输入时刻放到世界中，再投影到相机读取特征。深度残差、置信度与实例 / 语义筛选形成加权聚合。可靠自由空间由射线证据投票得到。

### 5.2 观测锚定的条件流补全

每类编码器将聚合特征映射到共同宽度潜码。令已见、自由空间和未知掩码分别为 \(m,f,u\)，则：

\[
u=1-m-f,\quad
z_0=m\odot z_{obs}+u\odot\epsilon,\quad
z_{\tau+\Delta\tau}=\Pi_{m,f}\left[z_\tau+\Delta\tau\,u\odot v_\theta(z_\tau,\tau,C)\right].
\]

\(\Pi_{m,f}\) 恢复已见潜码并清零自由空间。局部分组注意力维持单个规范区域的细节，全局记忆交换背景与资产条件。流时间 \(\tau\) 与在线仿真时间分别定义。

### 5.3 分类型解码与观测保护

解码器在每个支撑单元内预测多个高斯的中心偏移、协方差、不透明度和局部方向外观。人体子高斯继承模板权重。分别解码补全候选与仅观测基线，在原始相机和资产状态下验证 RGB、预测深度参考、覆盖率及新增前景侵入。

### 5.4 固定世界的状态装配

离线构建后的几何与外观固定。车辆接受整体 SE(3)，人体接受蒙皮和根变换；中心、协方差和局部方向映射共同更新。外部动力学更新状态，统一渲染器返回多相机观测。

### 训练顺序

1. 共享恢复前端：训练或适配几何、身份与状态预测，先校准置信度。
2. 冻结前端，训练 codec：部分输入与完整目标在**同一查询布局**上一一对应。
3. 冻结前端和 codec，用有完整有效潜目标的数据训练条件 Flow Matching。
4. 保持前端和 codec 冻结，通过可微积分、解码和渲染，用真实日志观测约束适配补全网络。

798 个真实训练场景不能自动提供所有未知查询的完整潜目标。`target_valid` 是当前实现的必要条件；完整合成数据或完整资产采集，以及同布局目标构造器，是训练补全先验的重要前置工作。

- 主阅读方向从左到右；核心联合补全占最大视觉面积。主图不展开存取文件、版本检查、异常分支等代码管理细节。

- 将“锁定已见”画成保持原蓝色 token 的通道，将“清零自由空间”画成空心单元及零不透明度约束；可靠潜码与新增遮挡检查不能混为同一操作。
- 在同一世界到多条轨迹之间画一对多分支；在线动作箭头只指向状态，避免读者误以为每步重新补全几何。
- 参考世界坐标表明离线条件关系；图中不将其画为实际碰撞推理或动态光照模块。
- 学习监督放入关联细节图：完整目标监督流匹配，部分真实日志监督可微渲染约束。主图中的训练 / 在线边界保持可辨。
- 初步按双栏宽约 178 mm、宽高比约 2.2:1 规划；主标签有效字号至少 8 pt，次级说明至少 7 pt。这是设计起点，投稿尺寸以目标届次模板为准。
- 目前没有实测渲染图可作为图中结果。设计稿中的场景对象用于解释机制；最终结果栏替换为可追溯的真实实验输出。

阅读层级：第一眼识别部分观测、联合补全、固定世界和多状态用途；仔细阅读时识别规范空间、已见 / 空域约束及状态控制；技术细节放到关联局部图。正式制图后再做物理尺寸、隐藏标题灰度与连线检查。

## 7. 数据划分与评价协议

### 用户数据与留出原则

- 798 个训练场景内先划开发集，例如 718 / 80，具体 scene ID 与抽样种子写入清单。训练、开发和评测按场景隔离；同场景窗口、相邻帧和重复资产不跨集合。可获得路段 / 时间信息时进一步检查关联片段。
- 所有超参数、采样步数、验证阈值和主指标在开发集确定。202 个官方验证场景作为论文冻结后的留出评测集，保持其官方验证集名称。
- 若正式训练使用全部 798 场景，先在内部开发集冻结配置和训练步数，再让主方法、基线与消融统一按该配置重训。不能用 202 场景选择模型、阈值或胜出主张。
- 固定相机、时间采样、输入分辨率、预处理、曝光 / 颜色约定和有效像素定义。改变输入视角数量、额外 LiDAR 或监督源时分别报告。

Waymo Perception 提供相机、LiDAR、标定、车辆位姿及实例标注，可作为真实日志来源，见[官方数据说明](https://www.waymo.com/open/about/)。完整隐藏表面、身份衣物模板和可用绑定需要另外落实；LiDAR 观测本身不等于完整三维真值。

### 三类主任务

| 任务 | 输入与留出 | 主指标 | 需要回答的问题 |
| --- | --- | --- | --- |
| T1：新视角与未见表面 | Waymo 留相机 / 连续时段；补充有完整真值的受控合成场景，固定未见区域定义 | 未见区域 LPIPS / PSNR；有独立几何真值时报告深度、表面距离 / F-score | 补全是否改善原观测未覆盖的内容？ |
| T2：观测保持 | 同一输入与同一原视角；评测所有预注册场景 | 已见区域绝对误差、相对退化、新增前景侵入、有效覆盖与拒绝率 | 新内容会否破坏原来正确的内容？ |
| T3：状态干预 | 同一固定世界；预定义相机偏移、车辆转向 / 位移、人体新姿态 | 有真值时的原始渲染质量、几何 / 轮廓误差、覆盖；在线延迟与显存 | 离线补全能否被新的状态实际使用？ |

真实场景的任意横向新轨迹通常没有配对 RGB 真值，不能拿原轨迹图像计算新轨迹 PSNR。配对指标用真实存在的留出相机 / 时刻，或受控合成 / 完整采集的新轨迹真值。无真值干预单列视觉、结构与有效域证据。

时间留出时，未来资产状态若作为受控输入使用，需明确注明，并向比较方法提供同等状态信息。新进入且输入未曾观测到的资产超出固定资产库覆盖时，单列身份覆盖与失败，不能静默排除后只报成功样本。

评测使用统一的外部有效像素 / 可见性定义，另报各方法自己的覆盖率。不可让每个方法只在自己的高置信像素上打分。观测验证的构建阈值与独立评测标准分开记录。

### 外部比较与机制对照分别组织

| 比较组 | 建议参照 | 对齐要求 |
| --- | --- | --- |
| 真实日志恢复 | OmniRe | 相同日志与评测相机 / 状态；列清 LiDAR、标注、额外监督、优化步数与构建成本 |
| 生成先验辅助高斯恢复 | StreetCrafter 的高斯表示分支 | 对齐输入及生成额外视图的预算；分别报告三维表示直接渲染与视频生成输出 |
| 可控生成 / 编辑 | WorldSplat、HorizonForge | 先确认代码、输入条件和评测适配可用；在相同状态编辑任务中比较，无法对齐的监督或条件单列 |
| 控制机制 | A1 无补全、A2 无跨组交换、2×2 观测保持实验 | 同一恢复前端与 codec，是判断所提机制收益的首要证据 |

LatentWorld、CompleteSplat、JRM 用于界定最接近思想。其中任务或输入明显不同的工作，可以做适配实验并说明变化，不强行纳入同一 RGB 排名。理想位姿 / 深度输入是诊断上界，真实预测输入是完整系统结果，分别列出。

## 8. 消融设计

### 主表：每一行回答一个机制问题

所有关键对照固定恢复前端、codec 版本、数据、查询布局、采样预算及评测状态。除纯推理策略对照外，结构消融重新训练。

| ID | 变体 / 干预 | 固定条件与实现要点 | 主要观测 |
| --- | --- | --- | --- |
| A0 | 完整方法 | 联合补全 + 双坐标条件 + 观测 / 空域约束 | 参照 |
| A1 | 无生成补全 | 非 known 查询不透明度关闭；复用同一观测恢复与 codec | 未见区域质量与覆盖的增量 |
| A2 | 禁止跨组联合交换 | 按背景 / 单资产隔离记忆读写，保留相同外部场景条件；尽量匹配参数与计算量，差异单列 | C001：联合信息是否有独立收益 |
| A3 | 去掉参考世界坐标 | 保留规范坐标、尺度与类型，避免同时删掉所有空间信息 | 场景相对关系条件是否有效 |
| A4 | 去掉可靠观测锚点 | 保持总查询容量，以预留支撑补足，避免把查询数减少误认为锚点作用 | 薄结构、已见几何与未见表面质量 |
| A5 | 去掉深度 / 遮挡门控 | 保留实例与语义及其余置信度流程，独立关闭深度一致性筛选 | 背景混入动态资产、纹理污染与侵入 |
| A6 | 去掉自由空间硬约束 | 同时处理标签条件、积分重置与解码器不透明度门控；重新训练对应模型 | 空域占据与错误遮挡 |
| A7 | 硬观测锁定改为软拟合 | 用预先调定的软观测目标训练；修改 velocity 的掩码、训练目标和积分覆盖逻辑 | C002：未见质量—已见退化权衡 |
| A8 | 固定世界下的人体驱动 | 同一规范人体，比较蒙皮与整体刚体放置；保持采样 / 渲染预算 | 人体新姿态质量；作为人体建模必要性对照 |

**需要避免无效消融：** `forward` 已将非 unknown 的速度清零，所以仅删除 `integrate` 的 known 覆盖操作基本不会改变已见潜码。自由空间又在解码器关闭不透明度，仅关闭一个位置也可能无法移除该约束。每种变体应检查实际输出是否发生预期变化。

### 关键交互：联合条件 × 观测保持

做联合 / 独立补全与硬锁定 / 软观测拟合的 2×2 设计。已见锚点、自由空间、codec 和采样预算保持一致。四个模型分别报告未见区域质量、已见退化、侵入与拒绝率。它检验联合建模是否带来收益，以及观测锁定是否以明显牺牲补全能力为代价。

### 补充分析

- 输入视角 / 时刻稀疏度、遮挡程度分层；车辆背面、人体背部、被移走资产后暴露的背景区域分开统计。
- 固定布局下的跨资产 token 交换强度和局部 / 全局记忆预算。
- 位姿、深度与实例关联误差的可控扰动；分别报告理想证据输入与真实预测证据输入，区分恢复误差和补全误差。
- 采样步数 4 / 8 / 16 / 24、查询容量和子高斯数的质量—成本曲线；几何 / 相机与单位不变。
- 将完成后的资产移至预定义新位置 / 朝向，并检查参考世界条件是否让几何过度依赖构建时放置。固定光照下评估，动态阴影与跨场景重光照另立问题。
- 训练种子和构建采样种子分别记录。不能挑一个最好世界种子作为所有场景的唯一结论。

同状态、同世界装配一致、车辆刚体距离不变、bind pose 还原与规范数组只读保留为数值回归检查。它们不替代 A2 或独立状态干预质量实验。

## 9. 64 张 H20 下的执行顺序

本节为资源分配建议，不启动训练，也不预估未经测量的训练时长。

| 阶段 | 建议工作 | 放行条件 |
| --- | --- | --- |
| P0：数据与监督验收 | 核对场景清单、数据适配、相机 / 深度坐标、人体拓扑；确认完整目标来源；在小批量上跑通监督与渲染 | 能得到可追溯的真实输入与同查询完整目标；损失与几何检查可信 |
| P1：最小机制实验 | 从内部训练部分抽 10–20 场景做训练试验，在独立开发场景与受控合成留出集验证；固定前端与 codec，比较 A0、A1、A2、A3 | 联合相对独立的差异可重复，质量增量不依靠覆盖率下降或拒绝率上升 |
| P2：规模化训练 | 按四阶段训练前端、codec、补全与真实观测适配；各阶段固定版本；先做 1 / 4 / 8 / 16 卡吞吐测量 | 选择实际有效的单任务卡数、全局 batch 和梯度累积；固定完整协议 |
| P3：核心证据 | A0 与 A2 至少各 3 个独立训练种子；完成 2×2 交互和主表消融；固定若干构建采样种子 | 主指标改善超过预先设定的实际效应阈值，并满足观测退化与失败预算 |
| P4：冻结评测 | 正式配置对全部 202 场景统一评测；所有失败、中断和未覆盖资产进入报告 | 场景级结果、成本、原始日志与图像能够逐项追溯 |
| P5：应用验证 | 固定策略、动力学和物理代理，仅替换视觉世界；比较同一初始状态与行为种子 | 先确认原始渲染质量与覆盖，再解释闭环行为变化 |

建议把部分 64 卡用于多个 8 / 16 卡实验并行，而非默认把小型 DiT 单任务扩到 64 卡。例如单任务 8 卡可同时运行 6 个主模型 / 关键基线种子和 2 个机制诊断任务；实际分配取决于吞吐、显存与共享存储表现。当前默认网络宽度 128，不据卡数直接决定模型规模。

初始小批量可从少量采样时刻、约 640×384 的统一图像网格开始，同步变换内参；所有方法遵循相同输入协议。完整长日志的时间 / 相机分块、稳定身份汇聚和特征缓存需要专门实现与验证，64 卡不能代替这一数据路径工作。

主指标围绕未见区域质量制定，另设已见退化、侵入和失败预算。最小实际效应阈值及容许退化由内部开发集与测量噪声确定，进入 202 场景评测前冻结。场景是主要独立统计单位，使用场景级成对汇总与置信区间，训练种子的结果分别报告；相邻帧或像素不充当独立重复。

如果联合补全持续不优于独立补全，就调整 C001 的机制或研究定位；如果收益只存在于理想位姿 / 深度条件，就优先修复证据恢复；如果只在高拒绝率下得到好图像，先解决质量与覆盖权衡。预算阈值需要 GPU 可用时长和吞吐实测后再制定。
