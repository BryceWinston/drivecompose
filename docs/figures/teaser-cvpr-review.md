## 3. 推荐改法：沿用当前骨架，按此顺序改

### 优先一：让“缺失 → 补全”成为中央图的可见动作

当前中央大车能吸引注意，但明确的补全前后比较在底部，读者需要向下读再折返右侧。上方两个蓝色操作框则有较高的色彩重量。

1. 将上方蓝框改成浅灰的紧凑操作节点。现高 89.25 单位，可先试约 50–54 单位并保留可读文字；腾出的区域优先给观测表面和目标视角下的缺失表面。无需更换全图配色。
2. 将缺失面画成灰色稀疏斜线或有清晰边界的空面；补全后对应位置使用金色实面。保持当前三维投影，让读者可以逐处找到同一位置。
3. 保留底部对照的信息价值，先把它改成中央场景附近的**同位置车尾局部对照**，使用短标签 `All inputs aggregated → Joint completion`。若之后将这项变化完整整合到主图，再合并原条带。不能仅为减少面板而直接删除。
4. 上方“观测重建”的终点与右侧相机变化结果使用可比的观察方向。当前两条路径的目标视角不便直接对齐，难把白色缺口和补全表面对应起来。

借鉴来源：DriveDreamer4D 的对应局部、ReconDreamer 的明确比较条件，以及 GenAssets 通过资产朝向展示完整性的方式。改的是比较逻辑，不复制其排版坐标或科研内容。

### 优先二：把右侧三张小全景改为“一张全景＋两个动作近景”

- **New camera view**：保留全场景，用简洁相机位置或方向提示说明变化来自给定相机状态。
- **Vehicle rotation**：让车辆占据该区域主体，保留少量地面方向线作为参照；加一条原生旋转箭头，使转动能在缩小后读到。原图中金色车尾在旋转图中仍位于车尾，是值得保留的有效对应。
- **Human articulation**：使用人体近景，明确显示骨架姿态变化以及同一补全表面随肢体变化。现有人体基本是紫色，单纯裁剪放大并不能补出缺少的金色表面说明；需要按方法含义补画明确标为机制示意的表面对应。

在三图上方或分支入口保留一条短说明：`Same assets, new states`。用相机、刚体、骨架的小符号或直接文字表明是给定控制量。无需添加新模块框，也不要画成随时间自主预测未来。

这里借鉴 UrbanCAD 的局部放大、HorizonForge 的“操作条件—结果”对应。保留现有示意图身份，不把新增示意当作实验输出。

### 优先三：让“联合”和颜色规则在缩小后仍成立

现有背景、车辆、人体到共享上下文的双向连接可以表达信息交换，值得保留。但图中只清楚展示了车辆的补全前后，读者还需要推断背景和人体是否也被补全。

1. 保留一个共享上下文单元，并把三类对象的补全标记接到同一解释中。可以在中央三个对象各保留一个简短局部标记，显示共享的是补全所用场景信息；不必把潜码和网络层全部搬进 teaser。
2. 青/蓝/紫继续表示组件身份，金色只表示已补全表面。Observed 图例目前只有蓝灰色，而实际观测部分还使用青色和紫色；应调整为多种观测类目色的组合示例，或在紧邻图例的短说明中明确这两套编码。
3. 选定一个车身表面和一个人体表面，用相同的小标记或边界在中央图及状态图中追踪。相机改变后可见金色面积可以变化；需要核对的是三维表面身份，不能要求两张投影中的金色面积相同。
4. 删除 `Also: rotation and articulation`，因为右侧已有两个对应标签。`Example frames` 可并入输入标题；补上输入两列的真实视角名称或简短 View 1 / View 2 标记，不臆造具体相机名称。
5. 将机制标签、图例和状态文字提高到可读尺寸，并检查文本框。字体本身已经统一，没有必要为“像录用论文”而全部更换字体。

**金色并未被证实画错。** 相机图中的金色范围更大，可由相机看到原本未观测的一侧解释。当前缺少可核对的表面对应；人体姿态图也没有清楚展示金色表面跟随骨架运动。建议修正的是这两项表达证据。
